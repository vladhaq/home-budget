# Домашний бюджет

Локальная система домашнего учёта. Собирает покупки из всех источников **до отдельных товаров**,
раскладывает их по категориям, сверяет с выпиской банка и показывает всё в веб-интерфейсе на `localhost`.

| Источник | Что даёт | Как попадает |
|---|---|---|
| Lidl Plus | чеки с позициями, скидками, способом оплаты | API приложения (вход в окне Chrome) |
| Kaufland Card | чеки с позициями, скидками, отделами магазина, залогом за тару | API приложения (вход в окне Chrome) |
| Фото/сканы чеков | любые магазины, наличные | Telegram-группа или папка, распознавание Tesseract (+EasyOCR) |
| Почта Gmail | онлайн-заказы (Allegro, Koleo, DOZ, Media Expert…), подписки, оплаты через PayU/Tpay/Przelewy24 | IMAP, только чтение |
| Банк PKO | все операции счёта, остаток, доходы | Enable Banking (PSD2, только чтение) |
| Выписка из файла | операции любого банка: CSV из интернет-банка, MT940, camt.053 | страница «Банк» или папка `bank/inbox/` |
| Наличные | сколько денег на руках, доход и траты наличными | твои записи + автоматически из выписки и чеков |

Газетки и скидки Lidl (поиск акций, напоминания в Telegram) — отдельный модуль: [lidl-deals/README.md](lidl-deals/README.md).

## Быстрый старт (первый запуск)

1. Установи **Python 3.13** с [python.org](https://www.python.org/downloads/) — при установке отметь
   **«Add python.exe to PATH»**. Для входа в Lidl, Kaufland и банк нужен **Google Chrome**,
   для фото чеков — **Tesseract** (см. [Установка](#установка)).
2. Открой терминал в папке проекта (в Проводнике: правый клик по папке → «Открыть в терминале») и выполни:
   ```
   pip install -r requirements.txt
   copy config.ini.example config.ini
   python budget.py serve
   ```
   Откроется браузер на `http://127.0.0.1:8765`. Сервер слушает только этот компьютер. Остановить — `Ctrl+C`.
   Пока источники не подключены, страницы пустые — база (`data/budget.db`) создаётся сама.
3. Подключи нужные источники — каждый один раз, все необязательные: [Настройка источников](#настройка-источников).
   Начать можно с одного, например Lidl Plus. Что подключено, а что нет — видно на странице **«Настройки»**.
4. Обновлять данные — одной командой или кнопкой «Обновить всё сейчас» на странице «Настройки»:
   ```
   python budget.py update
   ```
   Автозапуск каждый день (Планировщик заданий Windows): `python budget.py schedule on 07:30`.
5. Сделай пароль резервных копий: `python budget.py backup password` — дальше копии делаются при обновлении.

## Установка

1. **Python 3.13** и зависимости:
   ```
   pip install -r requirements.txt
   ```
   Фото чеков распознаются двумя способами: **Tesseract** (основной) и **EasyOCR** (перепроверка, когда сумма
   позиций не сошлась с итогом). EasyOCR ставится вместе со всем, но тянет PyTorch — это **~1–2 ГБ** и несколько минут
   установки. Если место или интернет ограничены — перед установкой удали строку `easyocr` из `requirements.txt`:
   всё будет работать, фото будут распознаваться только Tesseract. Поставить позже: `pip install easyocr`.
2. **Google Chrome** — нужен для входа в Lidl, Kaufland и банк. Подходящий драйвер скачивается сам
   (старый chromedriver в PATH игнорируется).
3. **Tesseract OCR** — для фото чеков:
   ```
   winget install UB-Mannheim.TesseractOCR
   ```
   Польский словарь скрипт скачает сам в `data/tessdata` при первом распознавании.
4. **Конфиг:** скопировать `config.ini.example` в `config.ini` и заполнить (см. ниже).

### Обновление программы
«Настройки» → **«Проверить обновление»**: если на GitHub вышла новая версия, видно, что в ней нового, и кнопка
«Установить и перезапустить» — программа скачает выпуск, заменит свои файлы, при новых зависимостях выполнит
`pip install`, и сервер перезапустится сам (страница обновится). То же из терминала:
```
python budget.py upgrade            # проверить и установить (спросит подтверждение)
python budget.py upgrade --check    # только проверить
```
- База, токены, `config.ini`, резервные копии и папки входящих не меняются; перед установкой — копия базы
  в `data/upgrade/`. Установка из `git clone` обновляется через `git pull`.
- Сервер перезапускается сам, если запущен командой `python budget.py serve` версии 1.2.2 или новее
  (`serve` следит за сервером и поднимает его заново после установки). С более старой версии один раз обнови вручную:
  скачай ZIP выпуска и распакуй поверх папки программы (или `git pull`), затем `pip install -r requirements.txt`.
- Программа выходит в сеть за обновлением только по кнопке или команде.

## Настройка источников

Каждый источник настраивается один раз. Пароли и коды **всегда вводишь ты сам** — в окне браузера
или в терминале; скрипты их не видят и не хранят. Сохраняются только токены доступа (см. [Безопасность](#безопасность)).
Вход в Lidl, Kaufland и банк можно делать и без терминала — кнопкой **«обновить токен»** на странице «Настройки»
(то же окно Chrome, что у `login`).

### Lidl Plus
```
python budget.py lidl login     # окно Chrome: вход как в приложении (email/телефон, пароль, код)
python budget.py lidl sync      # скачать новые чеки
```
- Скачиваются все чеки из приложения, исходники — в `data/lidl/raw/`.
- Старые чеки приходят списком позиций, новые (с весны 2026) — HTML; разбираются оба формата.

### Kaufland Card
```
python budget.py kaufland login
python budget.py kaufland sync
```
- Основа разбора — текст напечатанного чека: из него берутся скидки по строкам (`Pozycje:N`), залог за тару,
  отделы магазина (помогают с категориями), способ оплаты, сдача, последние цифры карты.
- Суммы позиций в API — уже после скидок; в базе хранится цена без скидки + скидка отдельно.
- API найден в открытом проекте [Bonfire](https://github.com/Naxter/bonfire), неофициальный — может сломаться.

### Фото и сканы чеков (Telegram)
В `config.ini`:
```
[telegram]
; ключи: https://my.telegram.org -> API development tools
api_id = ...
api_hash = ...
; ссылка-приглашение группы для чеков
receipts_chat = https://t.me/+...
```
Комментарии в `config.ini` — только отдельной строкой с `;`: в конце строки они станут частью значения.
```
python budget.py telegram       # первый раз спросит телефон и код Telegram
```
- Отправляй фото **как файл**, а не как фото — Telegram не сожмёт его, распознавание точнее.
- Форматы: jpg, jpeg, png, webp, heic, pdf. PDF с текстом читается без распознавания.
- Распознавание: 5 вариантов Tesseract → голосование по каждому полю → подбор позиций так, чтобы сумма сошлась
  с итогом чека. Не сошлось — перепроверка EasyOCR; одна позиция не прочиталась — её сумма вычисляется из итога (≈).
  Если всё равно не сошлось — чек сохраняется с пометкой «⚠ проверить вручную». Одинаковые товары в разных строках
  (два филе) — разные позиции; промежуточный итог и «OPUSTY ŁĄCZNIE» — не товары; количество Kaufland на отдельной
  строке («2SZT x7,99») понимается и в искажённом виде («25ZT», «152T»).
- **Насколько точно распознаёт** — `python tools/ocrbench.py`: каждое фото, продублированное электронным чеком
  Lidl/Kaufland, — тест с правильным ответом (итог, суммы и скидки по товарам, похожесть названий для Tesseract,
  EasyOCR и программы целиком). Чем чаще дублируешь чеки фото в Telegram, тем больше проверочная база.
- **Фото чека, который уже есть** (электронный чек Kaufland/Lidl, письмо): та же сумма, время ±15 минут, тот же магазин — фото не создаёт дубль, а прикрепляется к этой покупке («📷 фото чека · ✓ совпало с фото» в списке чеков). Если фото пришло раньше электронного чека, сверка склеит их позже сама.
- Без Telegram: положи файлы в `receipts/inbox/` и запусти `python budget.py photos`.

### Почта Gmail
1. Включи двухэтапную проверку Google и создай **пароль приложения**
   (Аккаунт Google → Безопасность → Двухэтапная проверка → Пароли приложений).
2. ```
   python budget.py mail login      # спросит адрес и пароль приложения; пароль — в диспетчер учётных данных Windows
   python budget.py mail headers    # заголовки писем с начала выписки (быстро, мало места)
   python budget.py mail senders    # статистика отправителей: кто похож на магазин
   python budget.py mail mark shop allegro.pl zalando.pl    # отметить отправителей
   python budget.py mail bodies     # полные письма — только от отмеченных
   python budget.py mail parse      # письма -> покупки
   ```
- Метки отправителей: `shop` — магазин, `sub` — подписка/связь, `pay` — платёжный посредник
  (PayU, Tpay, Przelewy24, Autopay), `ignore` — не нужно.
- Почта открывается только на чтение, письма не помечаются прочитанными.
- Свои разборщики: Allegro (позиции, продавцы, доставка, Allegro Smart, купоны), Koleo (цена из PDF-билета),
  квитанции Stripe (Anthropic и т.п., пересчёт из евро по курсу NBP). Остальные магазины — общий разбор:
  номер заказа, позиции («N x цена», таблица «Produkt / Ilość / Kwota», блоки «марка / название / размер /
  Ilość», магазины на IdoSell), доставка, скидка на заказ (делится по позициям), итог; запись к врачу — услуга.
- Письма одного заказа («принят / собран / выдан») склеиваются; оплаты посредников добавляются, только если у
  магазина нет своего письма с той же суммой. Описание платежа у посредника — название позиции (объявление OLX),
  а номер заказа в нём («Opis: 10900000000001») связывает оплату с письмом магазина.
- Письма скачиваются с начала банковской выписки (и за две недели до неё).

### Банк PKO (Enable Banking)
Выписка настроена под **PKO BP** (поиск банка и разбор операций). Другие польские банки Enable Banking тоже
поддерживает, но их формат операций здесь не проверялся — понадобится доработка `bank/enablebanking.py`.
Без банка всё остальное работает, просто не будет сверки и страницы «Банк».

1. Зарегистрируйся на [enablebanking.com](https://enablebanking.com), Control Panel → **API applications** →
   **Add a new application**: Environment **Production**, Redirect URL ровно `https://localhost/enablebanking`,
   ключ — «Generate in the browser».
2. Скачанный `<id>.pem` положи в `data/bank/`.
3. В карточке приложения — **Link accounts** → PKO BP → вход в iPKO.
4. ```
   python budget.py bank login     # окно Chrome: вход в iPKO и согласие; код перехватывается из адреса localhost
   python budget.py bank sync      # операции + остаток, затем автоматически сверка
   ```
- Согласие действует ~180 дней (дата — на странице «Банк», в «Настройках» и в `bank status`); потом повтори
  `bank login` или нажми «обновить токен» в «Настройках».
- Режим Restricted бесплатный, но видит только счета, привязанные в Link accounts.

### Выписка из файла (любой банк, beta)
Если банк не подключён (или нужна история старше подключения, или другой счёт) — выписку можно загрузить файлом:
кнопка «Добавить файлы» на странице «Банк», или положи файлы в `bank/inbox/` — их разберёт «обновить всё»
(разобранные переносятся в `bank/inbox/обработано`), или `python budget.py bank import <файлы>`.
- **Форматы:** camt.053 (XML по ISO 20022 — стандарт европейских банков), MT940 (поле `:86:` в польском виде
  `~20…` и немецком `?20…`), CSV из интернет-банка. В CSV колонки узнаются по заголовку — польские, английские,
  немецкие названия (iPKO, mBank, Millennium, ING, Revolut…), у файла без заголовка — по содержимому (даты, сумма
  со знаком, остаток, текст). Подробности iPKO в ячейках «Tytuł: …», «Lokalizacja: Adres: … Miasto: …» собираются
  в описание (у карты — магазин и город).
- **Тип операции** (карта, BLIK, банкомат, перевод, комиссия…) переводится в те же коды, что у подключённого PKO, —
  сверка с чеками, наличные и аналитика работают и с операциями из файла.
- **Без дублей:** операция того же счёта на ту же сумму в пределах 3 дней, которая уже пришла из банка или из
  прошлого файла, не добавляется. Файл без номера счёта при одном подключённом счёте считается выгрузкой этого же
  счёта; файл с номером другого счёта — отдельный счёт (остаток на графике и «всего на счетах» — сумма счетов).
- **Подробности к операциям из банка:** через подключение PKO отдаёт у BLIK только номер операции — без магазина
  и адреса. Та же операция в выгрузке iPKO (совпадает по «Numer referencyjny», иначе по сумме и дате) дописывает
  к ней адрес и получателя: «BLIK без названия» становится «example.nl», сверка и правила по магазину их узнают.
  Дописанное хранится вместе с ответом банка — пересборка выписки его не теряет.
- Копия загруженного через страницу файла — в `data/bank/imports/`.
- Твой банк не узнался или разобрался неверно — напиши, какой банк и какой формат (без своих данных): добавлю.

## Регулярное обновление

```
python budget.py update                 всё по очереди (1–2 минуты)
python budget.py update lidl bank       только выбранные шаги (сверка добавляется сама)
python budget.py update status          последние запуски: что обновилось, что сломалось
python budget.py schedule on 07:30      автозапуск каждый день
python budget.py schedule off | status
```

Шаги `update` по порядку:

| Шаг | Что делает | Если не настроено |
|---|---|---|
| `lidl` | новые чеки Lidl Plus | пропускается |
| `kaufland` | новые чеки Kaufland Card | пропускается |
| `mail` | новые письма; полные письма отмеченных отправителей | пропускается |
| `telegram` | новые фото чеков из группы | «не настроено» — нужен первый вход `python budget.py telegram` |
| `photos` | файлы из `receipts/inbox` (после распознавания переносятся в `receipts/inbox/обработано`) | — |
| `bank` | новые операции PKO | пропускается |
| `reconcile` | разбор писем, сверка с банком, наличные, категории | — |
| `deals` | свежие газетки Lidl; напоминания в Telegram по постоянным позициям | газетки обновляются; напоминания — после `python budget.py telegram` |
| `backup` | резервная копия, не чаще раза в `backup_every_days` дней (`config.ini` `[update]`, по умолчанию 1) | «не настроено» — задай пароль `backup password` |

- Ошибка одного шага не останавливает остальные. Каждый запуск записывается в журнал (таблицы `update_runs`,
  `update_steps`), он виден на странице **«Настройки»** и в `update status`.
- Входы здесь не запрашиваются: если вход устарел, шаг завершается ошибкой. У Lidl, Kaufland и банка в строке
  источника — дата входа, сколько токен уже работает, его **средний срок жизни** (от входа до отказа сервиса, по
  всем входам начиная с октября 2026) и кнопка **«обновить токен»**: откроется окно Chrome, вход — как в приложении.
  В «Обновить всё» она не входит. Почта, Telegram и пароль копий настраиваются один раз в терминале (`mail login`,
  `telegram`, `backup password`) — их команда видна в строке. После входа — «обновить» в строке источника.
- Автозапуск — задача `BudgetUpdate` в Планировщике заданий Windows, работает без окна (`pythonw`). Если компьютер
  в это время выключен или спит, обновление запустится при включении. Без интернета ждёт до 3 минут.
- Два обновления сразу не запускаются: второе сообщит «уже идёт».
- Новые отправители в почте не скачиваются сами: шаг почты отметит «!» и перечислит новые домены с письмами
  о покупках — посмотри `mail senders` и отметь (`mail mark shop <домен>`).
- Доступ к банку (PSD2) действует 180 дней: за 21 день до конца шаг банка и «Настройки» напомнят продлить
  («обновить токен» или `bank login`).

Отдельные команды (`lidl sync`, `bank sync`…) по-прежнему работают; `bank sync` сам запускает сверку.

## Интерфейс

`python budget.py serve` → `http://127.0.0.1:8765`.

Оформление — по мотивам Telegram: слева разделы в виде списка чатов (с подсказкой и счётчиками), справа содержимое.
**Светлая и тёмная тема** — кнопка в правом верхнем углу (по умолчанию — как в Windows, выбор запоминается).
**Поиск** в шапке — по названию товара или магазину, действует на обзор, неопознанные и операции банка (Esc — очистить).
Нажатие на «Бюджет» вверху сворачивает список разделов до иконок (повторное — разворачивает); на узком окне он свёрнут всегда, на телефоне — нижняя панель. Повторный клик по выбранному столбцу графика снимает выбор — снова «всё время».

**Фильтры** (на всех страницах, кроме «Настроек»): период, способ оплаты, магазин, категории (с поиском, **можно выбрать
несколько** — например «Еда» и «Табак и вейп»: нажимай по очереди, список не закрывается), источник.

- У **операции банка без чека** «для всех таких» — это **весь магазин или получатель** («все покупки в ALDI»,

## Как это устроено

### Категории
Дерево «категория › подкатегория»: 12 групп расходов (Еда, Алкоголь и табак, Дом и быт, Здоровье и красота,
Вещи и техника, Транспорт, Жильё, Связь и подписки, Досуг, Образование, Финансы, Прочее) + «Доходы» и «Переводы»
(не расход: Семья, Людям, От людей, Долги и возвраты, Снятие наличных, Между своими счетами).
Дерево задано в `core/categories.py` (`TREE`); у каждой системной категории — **постоянный ключ** (`food.meat`,
`transfer.atm`…). Код и словари обращаются к категориям по ключу, поэтому переименование и перенос в интерфейсе
ничего не ломают. Старая база перестраивается сама при первом запуске (слияния: «Мясо и рыба», «Овощи и фрукты»,
«Молочное и яйца», «Ремонт и инструменты»; новые: «Сладкая выпечка», «Бытовая техника», «Поезда и междугородние»,
«Продукты без чека»).

Категория позиции назначается по приоритету:
1. твоя ручная правка «только эта»;
2. твой комментарий к позиции («кофе», «такси», «обезболивающее» → словарь комментариев в `core/categories.py`);
3. правило по коду товара / точному названию (создаётся, когда меняешь категорию «для всех таких»);
4. **операция банка без чека:** возврат — категория исходной покупки; твоё правило по магазину / получателю;
   иначе — правило выписки (аренда, учёба, налоги, комиссии, магазины без чека…);
5. **позиция чека или заказа:** магазин, где название ничего не говорит (Jakdojade, Koleo → транспорт;
   Erecept → врачи); словарь ключевых слов (слитные названия Kaufland предварительно разбиваются на слова);
   товарная группа магазина; отдел магазина (Kaufland: «Słodycze», «Mrożonki»…); твоё правило по магазину;
   категория по умолчанию для магазина (аптеки, Media Expert…).

### Свои правила (`config.ini`)
То, что относится только к тебе — работодатель, вуз, свои заведения, небольшие города в выписке, — задаётся
в `config.ini`, а не в коде (секции `[bank]`, `[bank_rules]`, `[income_rules]`, `[merchants]`, `[shops]`,
`[shops_hint]`, `[mail_domains]`, `[mail_payees]`; формат и примеры — в `config.ini.example`). Поэтому копия
проекта для другого человека не содержит твоих данных.

### Сверка с банком (`reconcile`)
1. Каждая покупка ищет операцию в выписке: та же сумма, дата −3…+5 дней, совпадение магазина — приоритет.
   Если в письме Tpay есть номер операции BLIK («TR-…/88000000001»), покупка сверяется по нему точно —
   банк пишет тот же номер в описании.
   Покупки в евро — допуск 6% (курс и комиссия банка), сумма берётся из банка.
2. Несколько заказов одного магазина, оплаченных одной операцией (аптека), — склеиваются.
3. Тот же магазин, оплата до 14 дней после заказа, сумма отличается до 35% — «мягкое» совпадение,
   позиции пересчитываются под фактическую оплату.
4. Операции без чека становятся покупками «банк»; категория — по получателю/описанию (аренда, учёба, налоги,
   комиссии, Biedronka, Żabka…). Переводы людям и снятие наличных — категории «Переводы».
5. Возвраты на карту связаны с исходной покупкой (та же сумма или товар той же суммы за 90 дней, своя операция
   банка — тоже): минусом в её категорию и под тем же магазином, показываются внутри покупки.
6. **Под вопросом** — регистрация платежа без подтверждения (Przelewy24/PayU), которой нет в выписке, хотя выписка
   этот день уже покрывает, или повтор той же суммы через минуту: в суммы не идёт, пока не нажмёшь «оплачено».
   Письмо «Ekspres Przelewy24 — przekazano do realizacji» подтверждением не считается: платить мог другой человек.
7. Карты другого счёта определяются сами (ни одного совпадения при 5+ покупках); подпись — в `config.ini` `[cards]`.

Операции BLIK и оплаты картой, где банк вместо магазина передаёт номер, собраны в «магазины» «BLIK без названия»
и «Карта без названия» — опознавать их удобно комментариями.
Удалённые тобой покупки (таблица `hidden_purchases`) при пересборке пропускаются; вернуть — «Настройки» → «Удалённые покупки».

`python budget.py reconcile` — пересобрать покупки из исходников и сверить. Сама сверка повторяемая: суммы,
подогнанные под банк (мягкое совпадение, валюта), хранятся вместе с суммами из чека (`orig_*`) и в начале каждой
сверки возвращаются к ним, поэтому её можно запускать сколько угодно (интерфейс после удаления покупки пересверяет
без пересборки). Ручные правки категорий сохраняются.

### Наличные
- Твои записи: **пересчёт** (на руках сейчас), **доход наличными**, **расход без чека**.
- Автоматически: снятие в банкомате (+), взнос на счёт (−), чек с оплатой наличными (−).
- При пересчёте разница «расчёт − насчитано» — траты без чека (категория «Прочее › Наличные без чека»)
  или неучтённый доход.
- Банк сообщает только **дату** взноса/снятия. Время — интервал между двумя загрузками выписки, когда операция появилась; если твой пересчёт попадает внутрь интервала, операция помечена «уточни время» — кнопка 🕓 в «Движении наличных».
- События до твоей первой записи в кошелёк не учитываются: первый пересчёт — стартовая точка, а не «неучтённый доход».
- **Взнос наличных на счёт — доход** («Доходы › Наличные» у операции в выписке): так на вкладке «Банк» видно «получил / потратил». В кошельке взнос уменьшает наличные на руках. Записи кошелька «пришли наличные» и плюс при пересчёте в доходы не идут — только меняют остаток, чтобы одни деньги не посчитались дважды.

## Резервные копии

```
python budget.py backup password     # один раз: пароль копий (в диспетчер учётных данных Windows)
python budget.py backup              # создать копию
python budget.py backup list
python budget.py backup restore budget_2026-10-01_172002.zip
```
- Копия — ZIP с шифрованием AES-256 всей папки `budget`: база (согласованный снимок, можно при открытом интерфейсе),
  письма, фото, исходники чеков и выписки, токены, конфиги **и код**. Не входят только `data/tessdata`
  (скачивается заново) и временные файлы. ~60 МБ, ~10 секунд, после создания проверяется.
- Открывается 7-Zip / WinRAR с паролем. **Запиши пароль отдельно** — без него копию не открыть.
- Хранятся последние `keep` копий (по умолчанию 10). Вторая папка (`copy_to` в `[backup]`) — флешка или облако:
  копии зашифрованы, класть в облако можно.
- `restore` распаковывает в отдельную папку `budget_restore_…` рядом с `budget` — текущие данные не трогаются.
  Чтобы вернуть: закрыть интерфейс, сделать `backup` текущего состояния, заменить `budget\data` распакованной.

## Безопасность

Всё хранится локально. Сервер интерфейса слушает только `127.0.0.1`. Почта и банк — только чтение.

**Файлы с доступом к твоим аккаунтам — никому не отправлять:**

| Файл / место | Что это |
|---|---|
| `config.ini` | ключи Telegram API |
| `data/lidl/token.json` | доступ к Lidl Plus |
| `data/kaufland/token.json` | доступ к Kaufland Card |
| `data/telegram.session` | вход в твой Telegram |
| `data/bank/*.pem`, `data/bank/session.json` | ключ приложения Enable Banking и доступ к выписке |
| Диспетчер учётных данных Windows: `budget-gmail-imap`, `budget-backup` | пароль приложения Gmail, пароль копий |

Резервные копии содержат всё перечисленное — поэтому они зашифрованы.
Отозвать доступ: Lidl/Kaufland — сменить пароль; Gmail — удалить пароль приложения в аккаунте Google;
банк — Unlink / Remove в Control Panel Enable Banking или отзыв согласия в iPKO.

Перед правкой словаря или правил: `catsnap save`, после — `catsnap diff`: видно, какие позиции куда переехали и как
изменились суммы по категориям. Снимки — в `data/snapshots/`.
`reparse` — пересобрать базу из уже скачанных исходников (после правки разбора), без повторной загрузки.

## Проблемы и решения

| Симптом | Что делать |
|---|---|
| `Lidl/Kaufland не выдал токен`, `401` | вход устарел: «обновить токен» в «Настройках» (или `lidl login` / `kaufland login`) |
| `Согласие банка истекло` | «обновить токен» в строке «Выписка PKO» (или `bank login`) |
| `Нет связи с Enable Banking` | интернет моргнул; уже скачанное сохранено — запусти `bank sync` ещё раз |
| Gmail не пускает | нужен **пароль приложения**, а не обычный пароль; повтори `mail login` |
| Фото чека с пометкой «⚠ проверить» | открой «📷 фото», поправь категорию/позиции; в следующий раз отправь фото как файл |
| В покупке «проверить: в банке … без чека» | возможно, одна трата посчитана дважды (заказ + операция) — сверь вручную |
| Платёж «под вопросом», а он прошёл | платил картой другого банка — «оплачено» на странице «Неопознанные» |
| Много «Неопознанных» после нового магазина | разметь в интерфейсе — правила запомнятся |
| Порт 8765 занят | закрыть прошлое окно `serve` (или процесс python) |
| Сломалась база / нужно откатиться | `backup restore <файл>` → заменить `data` |
| На вкладке «Настройки» значок «!» | там же видно, какой шаг упал и какую команду выполнить; после неё — «обновить» в строке |
| Шаг с пометкой «ошибка в программе» | раскрой запуск в журнале → «вывод» и пришли текст Claude |
| Запуск «прервано: процесс… завершился» | компьютер выключили или закрыли окно посреди обновления; просто запусти ещё раз |
| Автозапуск не срабатывает | «Настройки» → Автозапуск: состояние и код последнего запуска; выключить и включить заново. Задача — `BudgetUpdate` в Планировщике заданий |

## Структура проекта

```
budget/
  budget.py              точка входа (все команды)
  config.ini             настройки и ключи (не в копиях для других!)
  app/                   веб-интерфейс: server.py (Flask) + static/ (index.html, style.css, js/*.js)
  core/
    db.py                схема базы (вся), миграции (PRAGMA user_version), запись покупок
    categories.py        дерево, словарь, назначение категорий, переименование/перенос
    reconcile.py         сверка с банком
    wallet.py            наличные
    analytics.py         аналитика: регулярные платежи, календарь, прогноз месяца
    kaufland_deals.py    газетки Kaufland (разбор PDF, поиск, история)
    prices.py            цены по чекам: история товара, личная инфляция
    backup.py            резервные копии
    upgrade.py           новая версия программы с GitHub («Проверить обновление» в «Настройках»)
    update.py            «обновить всё», журнал, автозапуск (Планировщик Windows)
    deals.py             скидки Lidl для интерфейса и «обновить всё» (подключает lidl-deals/lidl.py)
    browser_login.py     вход через окно Chrome (OAuth/PKCE)
    logins.py            дата входа и средний срок жизни токенов (страница «Настройки»)
    common.py            общие функции
  receipts/
    lidl.py, kaufland.py           чеки из приложений
    photos.py, textparse.py        фото чеков и разбор текста чека
    telegram_inbox.py              фото из Telegram
    mail.py, mail_parse.py, mail_orders.py   почта
  bank/enablebanking.py  выписка PKO
  bank/statement.py      выписка из файла: CSV, MT940, camt.053
  tests/                 тесты: словарь категорий, разбор писем и чеков после OCR (python -m pytest)
  tools/catsnap.py       снимок категорий «было → стало»
  tools/ocrbench.py      точность распознавания фото чеков (кэш текстов — data/ocr_cache/)
  lidl-deals/            газетки Lidl и напоминания (отдельный модуль)
  data/
    budget.db            база (покупки, позиции, операции банка, категории, правила, наличные)
    lidl/ kaufland/ bank/ mail/ photos/   исходники и токены
  backups/               резервные копии (по умолчанию)
```

**Основные таблицы `budget.db`:** `purchases` (покупка: источник, дата, магазин, итог, скидка, оплата, связь с
операцией банка, примечание), `items` (позиции и их категории), `payments`, `bank_tx` (операции выписки),
`categories`, `rules`, `wallet_entries` (записи о наличных), `emails` и `mail_senders` (почта),
`update_runs` и `update_steps` (журнал обновлений), `hidden_purchases` (удалённые покупки), `item_notes` (комментарии к позициям),
`confirmed_purchases` (платежи «под вопросом», которые ты подтвердил), `attachments` (фото к электронным чекам),
`wallet_times` (уточнённое время операций с наличными), `recurring_marks` (регулярные платежи, которые ты подтвердил или отклонил), `meta`. У покупки: `refund_of` — исходная покупка возврата,
`status = 'doubt'` — под вопросом, `orig_total` — сумма из чека до подгонки под банк.
